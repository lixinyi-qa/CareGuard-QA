# BUG-002 pending 绑定提前获得数据权限

- 类型：访问控制 / 缺陷注入与回归演练
- 严重度：S1；优先级：P0；状态：Verified
- 影响版本：fault-injection baseline；修复版本：1.0.0
- 前置：家属已发邀请，但老人尚未确认，关系为 pending

## 复现步骤

1. 家属创建绑定邀请。
2. 不执行老人确认。
3. 家属请求老人情绪、联系人或提醒接口。

预期：403，必须存在 `status=active` 的精确老人/家属组合。
注入基线实际：访问查询只判断 care_links 记录存在，pending 也被授权。

## 影响、根因与修复

未获得老人同意即共享数据，违反产品核心权限需求。根因是关系存在性查询遗漏状态条件。修复将所有共享资源统一收口到 `has_active_care_link()`，同时在 SQL 条件中校验 elderly_id、family_id、active 三项。

回归证据：`test_unlinked_family_cannot_read_moods`、`test_unlinked_family_cannot_create_reminder`、`test_unlinked_family_cannot_read_contacts`。
