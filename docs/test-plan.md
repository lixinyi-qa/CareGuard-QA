# CareGuard QA 测试计划

## 1. 测试策略

采用风险驱动与分层自动化：域规则在单元层快速反馈；HTTP 层覆盖状态码、字段、角色和数据隔离；MySQL 层验证真实驱动、字符集与关系结构；UI 层只保留高价值主路径和适老化交互；Postman 作为可演示的跨角色端到端回归；JMeter 验证典型写读混合负载；SQL 脚本验证数据库最终状态。

最高风险依次为：原始情绪文字泄露、未授权家属访问、告警文案造成医疗误导、关系撤销后权限残留、联系人明文暴露、数据孤儿/枚举非法值、适老化交互不可用。

## 2. 范围

### 范围内

- 身份认证、角色权限和会话错误处理；
- 双向同意家庭绑定及撤销；
- 情绪分类、否定词、高关注词、连续消极逻辑、模型卡；
- 提醒、联系人、关怀提醒和审计；
- API 合约、MySQL 数据质量、浏览器主路径、性能基准；
- 脱敏、越权、输入校验、响应安全头；
- 字号、高对比、键盘焦点、移动布局和明确反馈。

### 暂不在范围

- 短信验证码、真实消息推送和第三方急救服务；
- 临床诊断准确性、药品相互作用或剂量建议；
- iOS/Android 原生客户端；
- 生产级密钥托管、WAF、备份恢复演练和多地域容灾；
- 方言语音识别与大模型生成式对话。

## 5. 入口与出口准则

入口：需求基线冻结；OpenAPI 可访问；测试库可重建；演示数据不含真实个人信息；严重度口径评审完成。

出口：P0/P1 未解决缺陷为 0；自动化主流水线全绿；50 条用例有结果；隐私负向用例全部通过；数据检查为 0；README 的测试数字与实际报告一致。任何未执行项必须明确写为“目标/待验证”，不得写入简历成果。

## 6. 缺陷管理

严重度：S1 数据泄露/安全或核心服务不可用；S2 核心功能错误且无可接受绕过；S3 局部功能/兼容问题；S4 文案或轻微视觉问题。优先级由用户影响、发生概率和修复成本共同决定。每个缺陷包含环境、前置条件、最小步骤、预期、实际、证据、根因、修复、回归用例和状态。

`docs/defects/` 中 BUG-001 至 BUG-010 为“缺陷注入与回归演练”，用于展示报告质量，并非虚构生产事故；BUG-011 是真实 Chrome 回归发现的预发布缺陷。对应问题均由自动化用例证明当前版本已修复。

## 7. 性能模型

基准场景默认 20 用户、20 秒升压、每人 5 个循环。每个虚拟用户仅注册一次，每轮依次执行情绪写入、统计读取、提醒写入，并有 200–700ms 思考时间。正式报告至少记录吞吐、平均、P90/P95/P99、错误率、CPU/内存和数据库连接情况；本地硬件结果不外推到生产容量。

## 8. AI 功能评估

使用版本化、均衡的中文句子集计算 Accuracy 与 Macro Precision/Recall/F1，并单独计算高关注表达召回。必须覆盖无关键词、否定、混合情绪、口语化和高关注表达。规则模型的置信度只是“规则命中强度”，不是统计概率。失败样本进入已知限制，不能通过更改期望标签掩盖。

## 9. 风险与缓解

| 风险 | 可能影响 | 缓解 |
|---|---|---|
| SQLite 与 MySQL 行为差异 | 本地通过、正式环境失败 | 独立 MySQL CI 作业 + 24 项 SQL 检查 |
| 规则模型对反讽/方言失准 | 情绪提示错误 | 模型卡、三分类、非医疗声明、版本化评估集 |
| UI 本地存储令牌受 XSS 影响 | 会话泄露 | CSP、输出转义、安全头；生产建议迁移 HttpOnly Cookie |
| 告警疲劳 | 家属忽视提醒 | 七天内未确认连续消极提醒去重 |
| 自动化数据污染 | 集合重复运行失败 | Postman/Playwright 生成唯一测试手机号 |

## 10. 交付证据

自动化报告、AI 评估 JSON、必要截图与最终核验摘要写入 `outputs/`；源码、集合和设计文档保留在仓库。任何测试失败会保留错误输出而不是删除证据。
