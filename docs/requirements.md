# CareGuard QA 需求规格说明书（SRS）

> 项目性质：个人测试工程项目 / Personal QA Engineering Portfolio Project
> 版本：1.0
> 基线日期：2026-08-24

## 1. 项目目标与边界

CareGuard QA 面向能够独立使用手机或在家属协助下使用数字产品的老人，提供低认知负担的日常关怀工具；同时作为测试工程作品，展示需求分析、风险测试、接口/UI 自动化、数据一致性、性能、隐私和 AI 功能评估能力。

平台只做三分类日常情绪提示（积极/中性/消极），不输出疾病名称、诊断结论、药物剂量或治疗方案，不替代医生、心理咨询师、急救服务或家属的现场判断。高关注词和连续消极记录只生成通用关怀提醒，不自动联系外部人员。

## 2. 用户与权限

| 角色 | 可执行操作 | 明确禁止 |
|---|---|---|
| 老人 | 注册登录；本人情绪打卡；查看本人完整历史；确认/解除家属绑定；管理本人提醒和联系人；查看告警；导出本人数据 | 替其他老人打卡；访问他人数据 |
| 家属 | 注册登录；按手机号邀请老人；在老人确认后查看分类/统计、提醒、脱敏联系人和告警；维护已绑定老人的提醒和联系人 | 未确认即访问；读取原始情绪文字；替老人打卡 |
| 管理员 | 预留审计和运营权限，本版本不提供前端入口 | 业务人员默认获得管理员权限 |

## 3. 功能需求

### FR-AUTH 身份与会话

- FR-AUTH-01：老人和家属均可用姓名、中国大陆手机号、密码、隐私同意版本注册。
- FR-AUTH-02：手机号必须唯一且符合 `1[3-9]xxxxxxxxx`；密码为 8–72 位且同时包含字母和数字。
- FR-AUTH-03：隐私同意未勾选时不得注册。
- FR-AUTH-04：登录成功返回有时效的 Bearer Token；失败信息不得帮助枚举账号。
- FR-AUTH-05：任何用户响应不得返回密码或密码哈希；手机号默认按前三后四脱敏。
- FR-AUTH-06：停用账号不能登录或继续使用旧令牌。

### FR-LINK 家庭关怀绑定

- FR-LINK-01：仅家属可按手机号发起老人绑定邀请。
- FR-LINK-02：邀请创建后状态为 `pending`，此时不得读取老人业务数据。
- FR-LINK-03：仅被邀请老人本人可接受邀请，接受后状态为 `active` 并记录时间。
- FR-LINK-04：任一关系成员可解除绑定；解除后所有共享权限立即失效。
- FR-LINK-05：同一老人/家属组合只能存在一条关系记录。

### FR-MOOD 情绪打卡与分类

- FR-MOOD-01：仅老人可提交 1–500 字非空文本。
- FR-MOOD-02：系统只返回 `positive`、`neutral`、`negative` 三类，并提供中文显示值、0–100 置信提示和非医疗声明。
- FR-MOOD-03：老人可查看自己的原始文本和分类；已绑定家属只能看到分类、时间、置信提示和统计，`text` 必须为 `null`。
- FR-MOOD-04：最近三条均为消极时生成一条中等级别关怀提醒；七天内未处理的同类提醒不得重复生成。
- FR-MOOD-05：透明规则词表识别高关注表达，生成高等级通用关怀提醒；提醒中不得复制原始文字。
- FR-MOOD-06：系统提供 1–365 天统计，三类计数之和必须等于总数。

### FR-REM 提醒

- FR-REM-01：提醒分用药、日程两类，支持单次、每天、每周。
- FR-REM-02：老人可管理本人提醒；已绑定家属可为对应老人新增、修改、完成或删除提醒。
- FR-REM-03：提醒必须含标题、到期时间、类型；备注最多 500 字。
- FR-REM-04：平台不提供药物剂量推断，备注中的用药信息仅为用户输入内容。

### FR-CONTACT 与 FR-ALERT

- FR-CONTACT-01：联系人含姓名、手机号、关系、1–5 联系优先级。
- FR-CONTACT-02：仅老人本人、已绑定家属或管理员可维护；所有列表/新增响应均返回脱敏姓名和手机号。
- FR-ALERT-01：老人本人和已绑定家属可查看关怀提醒。
- FR-ALERT-02：提醒可确认一次，记录确认人和时间；二次确认返回冲突。
- FR-ALERT-03：提醒文案不得声称诊断，也不得包含情绪原文。

### FR-PRIVACY 治理与可追溯

- FR-PRIVACY-01：注册、登录、绑定、情绪、提醒、告警、联系人、导出等关键动作写入审计日志。
- FR-PRIVACY-02：普通用户只能读取自己作为操作者的审计记录。
- FR-PRIVACY-03：用户可导出本人身份、情绪、提醒和联系人 JSON 数据。
- FR-PRIVACY-04：系统公开 AI 模型卡，声明用途、禁用范围、局限性与隐私策略。

## 4. 非功能需求

| 编号 | 需求 |
|---|---|
| NFR-01 可用性 | 核心按钮触控高度不低于 42px；默认 18px 基准字号；支持两档以上放大、高对比和键盘焦点。 |
| NFR-02 反馈 | 成功、失败、空状态、待确认和已完成均需有文字反馈，不能只靠颜色传达。 |
| NFR-03 性能 | 基准环境下核心读取 P95 < 1s、写入 P95 < 1.5s、错误率 < 1%；以 JMeter 报告为验收证据。 |
| NFR-04 安全 | bcrypt 密码哈希、JWT 时效、最小权限、结构化错误、CSP、禁止 iframe、MIME 嗅探保护。 |
| NFR-05 数据 | MySQL 8.4、utf8mb4；24 项 SQL 一致性检查全部为 0。 |
| NFR-06 兼容 | 最新两个主版本 Chromium；桌面 1280px 及以上、移动 375px 及以上。 |
| NFR-07 可测试 | OpenAPI 合约、请求关联 ID、确定性规则模型、独立 SQLite 测试库、MySQL 集成作业。 |
| NFR-08 可维护 | 配置从环境变量读取；容器以非 root 用户运行；CI 分 API、MySQL、UI 三条流水线。 |

## 5. 数据与隐私分级

| 数据 | 分级 | API 展示规则 | 保留策略（建议） |
|---|---|---|---|
| 密码哈希 | 高敏 | 永不返回 | 账号存在期间 |
| 原始情绪文字 | 高敏 | 仅本人/管理员 | 用户可导出；生产应支持删除请求 |
| 手机号/联系人 | 高敏 | 业务响应脱敏；本人导出原值 | 用户可导出；解除关系不扩散副本 |
| 情绪标签/趋势 | 敏感 | 本人和已绑定家属 | 与原始记录一致 |
| 提醒 | 敏感 | 本人和已绑定家属 | 业务需要期间 |
| 审计日志 | 受限 | 仅操作者本人/管理员 | 生产建议 180 天以上 |

## 6. 验收标准

1. `pytest -m "not ui and not mysql"` 全部通过且应用代码覆盖率不低于 75%。
2. 7 条 Playwright 核心流程在 Chromium 通过。
3. Postman 集合从空库顺序运行时请求断言全部通过。
4. MySQL 合约测试确认连接、utf8mb4 和核心表。
5. 24 项 SQL 检查返回 `issue_count=0`。
6. JMeter 基准负载满足嵌入的响应时间断言，最终性能数字只引用实际报告。
7. 50 条功能用例完成设计评审；10 条缺陷演练记录和 1 条真实预发布缺陷均有自动化回归证据。
