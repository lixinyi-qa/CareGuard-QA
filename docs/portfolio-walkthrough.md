# CareGuard QA：3 分钟项目导览

## 这个项目解决什么问题

CareGuard QA 用一个可运行的适老化情绪关怀平台，展示软件测试岗位需要的完整质量闭环：需求分析、风险识别、用例设计、接口/UI/数据库/性能测试、缺陷复现、回归验证和证据留存。

项目特别关注双角色授权、老人明确同意、原始情绪文字隔离、联系人脱敏与非医疗边界。这些规则都落到了接口实现和负向测试中，而不只是写在说明文档里。

## 建议查看顺序

1. 打开 `README.md` 查看架构图、实测基线和四张界面截图。
2. 阅读 `docs/test-plan.md`，了解风险分级、测试范围和退出准则。
3. 阅读 `docs/test-cases.md`，抽查权限、隐私、边界值和状态流转用例。
4. 阅读 `docs/defects/BUG-011.md`，查看真实异步表单缺陷的复现、根因、修复和回归。
5. 查看 `tests/`、`postman/`、`sql/` 和 `.github/workflows/quality.yml`，核对自动化与CI实现。

## 面试时可以现场演示什么

- 使用演示账号完成老人端情绪打卡，再切换家属端验证“只显示标签、不返回原文”。
- 在 Swagger 或 Postman 中构造未授权、绑定待确认、解除关系后的负向请求。
- 执行快速 pytest 套件并解释覆盖率、跳过项和数据库合约测试的区别。
- 打开 `BUG-011`，说明如何从浏览器现象定位到 `await` 后 `event.currentTarget` 失效。
- 运行 SQL 一致性检查，解释为什么接口测试通过仍需要数据层校验。

## 真实性边界

- 情绪模块是可解释的规则基线，不是临床模型。
- JMeter结果是本机基线，不代表生产容量。
- `BUG-001` 至 `BUG-010` 是缺陷注入与回归练习；`BUG-011` 是实际发现的预发布缺陷。
- 所有账号和测试数据均为虚构数据。
